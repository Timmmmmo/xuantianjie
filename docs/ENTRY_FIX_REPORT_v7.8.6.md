> 事故一句话：**线上玩家打开游戏，主界面只剩「日课 / 签到 / 周常」，找不到也点不到「踏入战场」，进不去主游戏。**
> 修复版本：`v7.8.6-mr` · 修复日期：2026-09-20 · 验证：`node tools/gate.js` 全绿（8/8）

## 2. 根因：三层叠加，缺一层都不会出事

### ① 信息架构层 —— 回访壳排到了主入口之前
`index.html` 开始页把 `日课盒(227px) + 签到盒(147px) + 周常盒(103px)` 放在「踏入战场」按钮**上面**，
三盒合计 **477px**，加上标题/战绩/角色行，主入口被顺推到了第 978px 的位置。

### ② 布局层 —— 超高内容被「上下同时裁掉」，且没有任何滚动出口
```css
html, body { overflow: hidden; }
body { position: fixed; height: 100dvh; overflow: hidden; }   /* 页面本身永不可滚 */
.screen { display: flex; align-items: center; justify-content: center; }
.start-inner { max-height: 100%; }   /* 有上限，但没有 overflow → 溢出部分直接被裁 */
```
flex 居中 + 子项超高 = 内容向上下两侧对称溢出，**溢出的部分既看不到也滚不到**。
真机实测：内容高 **1128px**，可视高 **860px**，溢出 **268px**。

### ③ 触摸层 —— 即使给它加上滚动容器，真机上照样滑不动
```css
html, body { touch-action: none; }   /* ← 元凶 */
#app { touch-action: none; }
```
`touch-action` 的生效值是**元素自身与各级祖先的交集**，祖先写了 `none` 就等于把这个子树的手势全禁了。
所以第 ② 层即使补上 `overflow-y:auto`，在手机上依然是个「滚不动的滚动区」—— 兜底被二次封死。

## 4. 修复内容（逐层对应，缺一不可）

### ① 架构：主入口回到首屏，回访壳收进可折叠「修行录」
- 开始页顺序改为：**标题 → 战绩 → 角色 → 〔灵石商店 / 万宝图鉴 / 踏入战场〕→ 快捷项 → 修行录 → 版本**
- 日课 / 签到 / 周常 三盒移入 `#revisitPanel`，**默认折叠**，头部徽标显示
  `日课 x/3 · 签到 +N 可领 · 周常 progress/target`，有奖励可领时高亮
- 折叠状态记档（`localStorage`）；**玩家手动展开过就尊重他的选择**，不再自动收起
- 主入口与回访壳的关系：**入口永远在前，回访壳一次点击可达** —— 回访价值保留，但不再挡路

### ② 布局：给开始页兜底滚动 + 横屏专门排版
- `.start-inner { overflow-y: auto; overscroll-behavior: contain; -webkit-overflow-scrolling: touch; }`
  —— 将来再加内容，玩家最多滚一下，不会再有「够不到的按钮」
- 横屏 / 矮屏（`orientation:landscape and max-height:560px`）改为**两列网格**：
  左列「标题 + 战绩 + 角色 + 开战」，右列「快捷项 + 修行录 + 版本」，并压扁标题与按钮
  —— 横屏 414px 高度下主入口也无需滚动即可完整点击

### ③ 触摸：把「禁手势」收敛到玩法层
- `html, body, #app`：`touch-action: none` → **`pan-y`**（只放行纵向平移，双击/双指缩放仍禁用）
- 新增 `.screen { touch-action: pan-y }`，菜单类界面可拖滚
- **玩法期手势控制不受影响**：`.joy-zone` / `.skill-btn` 仍是 `touch-action: none`，
  且摇杆绑定本身带 `if (G.state !== "play") return` 守卫，菜单期从不抢触摸

### ④ 守卫：尺寸一变就重新巡检（防止「修一次、换机型又漏」）
新增 `syncStartLayout()`：回菜单 / 转屏 / 改窗 / 内容尺寸变化 / 字体加载完成 / 启动后 0.6s·1.8s
共 6 个时机各巡检一次。若主入口不在可视区 → 自动收起回访面板并把入口滚进视野。

## 6. 为什么门禁当时没拦住，这次补上了什么

**复盘**：v7.8.5 的 4 项门禁（语法 / 版本 / 冒烟 / 四套探针）当时**全绿**，但它们全部在 Node 桩里跑逻辑 ——
`index.html` 只被当**文本**读来核对 id 和版本号，**没有任何一项去量「按钮到底在不在屏幕上」**。
这是一个盲区：**逻辑正确 ≠ 界面可用**。

**新增防线**：
| 防线 | 内容 |
|------|------|
| 门禁 5 · 入口可达性 | `tools/entry-audit.js` 真机量测，已并入 `tools/gate.js`，不绿禁止部署 |
| 冒烟 64 · 架构断言 | 「踏入战场」必须排在「修行录」之前；三盒必须在 `#revisitBody` 内；必须默认折叠；`touch-action` 必须是 `pan-y`（不能回退成 `none`） |
| 运行时守卫 | `syncStartLayout()` + `ResizeObserver`，尺寸变化即自愈 |
| PM 手册 | 门禁表新增「入口可达性」；真机必测清单新增第 0 条「首屏主入口在各机型上完整可见、直接可点」 |

## 7. 遗留与建议

| 级别 | 项 | 建议 |
|------|----|------|
| P2 | 横屏为紧凑两列（非独立美术方案），视觉上不如竖屏舒展 | 若后续要主打横屏，出一个专门排版 |
| P2 | 弱机（320×568）仍会溢出 45px，靠滚动 + 守卫兜住主入口 | 可考虑在 `max-height:640` 下进一步压缩 |
| P3 | 回访壳默认折叠，短期回访曝光下降 | 用徽标高亮 + 红点补足；一周后看「签到领取率」判断是否需要在首屏给一条高优提示 |
| P3 | `docs/PM_OPERATING.md` 中的路径（`game/index.html`、`.deploy/verify.js`）与实际仓库结构不一致 | 另行清理文档漂移 |
