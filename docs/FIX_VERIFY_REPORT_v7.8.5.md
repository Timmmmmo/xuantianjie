## 2. P1-1 · 冒烟用例波次（悟道突破）

**现象**：`== 54) v7.1 · 悟道突破` 恒 FAIL —— 断言「升级后 `state` 应为 `level`、卡面 3 张」，实际 `state="play"`、卡面 0 张。

**根因**：用例断言的是「第 11 波起的手动三选一」，但 `forcePlay()` 不重置波次。用例落在前 10 波（v7.5「自动悟道」期）时，`update()` 走的是自动发卡分支：

```js
if ((G.pendingLevel||0) > 0 && G.state === "play") {
  if (autoUpgradePhase()) flushAutoUpgrades();   // G.wave <= 10：自动发卡，不弹窗
  else { openLevelUp(); ... }                    // 第 11 波起才弹三选一
}
```

**修复**（`tests/logic-smoke.js` 用例 54）：
- 显式把波次推过自动期：`G.wave = X.AUTO_UPGRADE_MAX_WAVE + 1`，确保测的是弹窗分支；
- 补一条**反向断言**：回落到前 10 波时，升级必须「不弹窗、不打断、自动放发」（锁住 v7.5 设计，防回归）；
- 用例末尾 `G.wave = waveSave54` 还原波次 —— 用例共享同一份全局状态，临时改动必须回收。

修复后该用例输出：`PASS 三选一弹窗（第 11 波起）+ 前 10 波自动悟道不打断，两条分支均正确`。

## 4. P1-3 · 重跑门禁挖出的更大问题：冒烟结果不可复现

修完上面两项后重跑，冒烟仍是红的，而且**每次红的不是同一条**。深挖后发现这是比原 2 项 P1 更严重的问题。

### 4.1 证据：把**原始线上用例**（未改动）连续跑 20 次

| 结果 | 次数 |
|------|------|
| 悟道突破异常（确定性） | **20 / 20** |
| 额外：濒死狂血异常 | 3 |
| 额外：applyHit 未接入五行 | 2 |
| 额外：词缀行为异常 | 1 |
| 额外：灵石槽加成异常 | 1 |
| 额外：掉率或灵石归属异常 | 1 |

即：**20 跑 20 红**，且除确定性那条外，还有 5 条断言会随机变红。这样的门禁不可能作为发布依据 —— 它红是常态，绿是运气。

### 4.2 根因

测试桩**完全没有控制随机数**（`tests/logic-smoke.js` 里只有 1 处 `Math.random`，是测试自己用的），而 `game.js` 有 **42 处 `Math.random()`**（掉率 / 词缀 / 暴击 / 连锁 / 悟道卡池 / 敌人元素 ……）。于是每次跑都是**一条不同的随机轨迹**，用例结果随轨迹漂移。

### 4.3 修复：注入确定性随机数

在测试沙箱注入固定种子的 `mulberry32`，替换沙箱的 `Math`：

```js
const rng = mulberry32(SEED);          // 默认种子 20260920
const MathShim = Object.create(Math);
MathShim.random = () => rng();
// sandbox = { ..., Math: MathShim, ... }
```

- 默认固定种子 ⇒ **门禁可复现**（同种子必同结果）；
- `XTJ_SEED=<int>` 可换种子做**模糊测试** —— 换种子后若某断言红，说明那是真脆弱点，应修断言而不是换种子。

### 4.4 顺带发现并修掉 4 条脆弱断言

固定种子后逐种子扫描，暴露出 4 条「测试没控制自己的输入」的断言，全部修复（都是让用例自洽，不是放宽标准）：

| 断言 | 随机来源 | 修复 |
|------|----------|------|
| `濒死狂血异常` | 狂血诀卡会抬高阈值/延长时长，`_frenzyT` 变 6s 而非 5s | 测前归零 `_frenzyHpAdd / _frenzyTimeAdd` |
| `applyHit 未接入五行` | v7.3 变类卡累积 `_elemBeatAdd`，对金一击从 135 变 155.25 | 测前按游戏自身 `resetRun` 口径归零 `_burstCut/_afterLifeAdd/_afterDmgMul/_afterExtra/_execLv/_zoneLv/_elemBeatAdd/_stoneBoostAdd` |
| `满员转化异常` | 上一步 `frames()` 若触发暴击**顿帧**，`update()` 在 `if (G.hitStop > 0) return;` 处直接返回，拾取逻辑整段被跳过（实测此时 `G.pickups` 仍为 1） | 测前 `G.hitStop = 0` + 清场 + 归位坐标 |
| `掉率或灵石归属异常` | 跨派系比例只有 ~60 个样本（灵石掉率 0.8%），固定 ±15pt 相当于 2.4σ，必然偶发误报（实测 21%~55% 都出现过） | 容差改为按实际样本量算的 4σ 置信带（小样本自动放宽，下限仍 15pt；真配置错误如「跨派系完全不掉」依然会红） |

### 4.5 验证：模糊测试

| 阶段 | 默认种子 | 多-seed 模糊 |
|------|----------|--------------|
| 仅注入种子 | 140 PASS / 0 FAIL | 7 / 12 全绿（暴露 4 条脆弱断言） |
| 修完 4 条断言后 | 140 PASS / 0 FAIL | **28 / 28 全绿** |
