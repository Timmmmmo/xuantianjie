# 《玄天劫》MVP 可行性分析

> 角色：小米高级游戏产品 / Product Design  
> 基线：**v7.8.7**（Canvas2D 零依赖 H5/PWA，已上线）  
> 范围：是否值得继续做、做到什么程度、风险与门禁

---

## 1. 一句话结论

**可行，适合继续做「高完成度 H5 割草 MVP」**；不建议在本阶段投入 3D 重制或服务端重架构。  
技术底座已验证（零依赖、PWA、jsdom 门禁），核心循环与回访壳齐备；主要风险在**获客与长期留存**，不在「能不能做出来」。

**MVP 成功定义（建议锁死）**
1. 单局 3–8 分钟可完成循环（走位 / 自动清怪 / Build）
2. 三角色差异可感知（克制 + 视觉）
3. 打开即主界面，首局 ≤30s 理解
4. 日课 + 签到 + 周挑战能支撑 **D1 有意义回访**
5. 中端机（Redmi 级）可玩、可离线
6. 变现仅自愿 IAA，不伤核心手感

---

## 2. 产品可行性

| 维度 | 评估 | 证据 / 缺口 |
|------|------|-------------|
| 核心循环 | **强** | v7.7 炼宝/装备/图鉴/试炼 + 割草密度；克制数值已调 |
| 上手成本 | **中上** | v7.7 教程 + 主界面 CTA；系统偏多，仍有学习债 |
| 回访 | **中** | 签到/日课/周挑战已有；赛季与推送未做 |
| 传播 | **弱** | 有分享卡，无好友榜/裂变激励落地 |
| 变现 | **中** | IAA mock + 去广告骨架；未接真实 SDK、无 eCPM 数据 |
| 竞品位置 | **中** | 玩法对齐幸存者主流，但美术/音效完成度低于头部小游戏 |

**目标用户**：碎片时间、单手竖屏、中端安卓（含 Redmi）。  
**场景**：通勤 / 课间 / 睡前 5–8 分钟。

---

## 3. 技术可行性

| 项 | 结论 |
|----|------|
| 引擎 | 纯 Canvas2D + 原生 JS，**已上线且可维护** |
| 性能 | 已有 Quality 三档；大批量怪时需盯渐变/粒子预算 |
| 离线 | PWA Service Worker 已具备 |
| 测试 | `logic-smoke` + jsdom `verify.js`（约 80 项）可回归 |
| 3D / three.js | **不建议进主包**：与零依赖/包体/中端机目标冲突；可作独立视觉实验 |
| 外部资产 | TRIPO/GEMINI/ELEVENLABS **密钥均缺**；立绘可用内置 image_gen，正式量产需预算 |

**性能风险**：`drawEnemyBody` 每帧渐变、同屏 80+ 怪时低端机掉帧 → 用缓存/降档可压。  
**工程风险**：`game.js` 仍为巨石文件（~8.7k 行）→ 新功能优先 `game/js/*` 壳模块。

---

## 4. 美术与表现（本周期投入）

| 表面 | 现状 | MVP 建议 |
|------|------|----------|
| 角色 | 程序化圆核 + 职业符号 | **提高**：光晕分层、职业剪影强化 + 选角用生成立绘 |
| 敌人 | 剪影已重塑（狐/狼/傀儡/蝶…） | **保持并强化** rim/顶光 |
| 攻击特效 | 剑气弧 + 弹道已有 | **提高**：多层弧、火花、暴击星芒、技能起手更“有手” |
| UI | 修真风暗金 | 保持 |

生成 3D 模型（Tripo）在无 key、无 three.js 管线时 **不可行**；2D 概念图 / 立绘 **可行**。

---

## 5. 商业与合规

- IAA 自愿位（结算翻倍、补签）符合「不挡正局」门禁  
- 无内购数值、无未成年人博彩设计  
- 原创修真包装，避免魔兽 IP 对外宣发  
- 存档仅本地 localStorage → 换机丢档，商业化前需云存档方案  

---

## 6. 里程碑与工作量（粗估）

| 阶段 | 内容 | 量级 |
|------|------|------|
| **本包** | 特效/角色表现 + 可行性 | 1 个 Compose 周期 |
| 2 周 | 真实 IAA SDK 适配层、分享裂变 | 中 |
| 4–6 周 | 赛季/本机榜/云存档草案、音效包 | 中高 |
| 可选 | Three.js 视觉 demo（独立仓库） | 高，**非 MVP 必需** |

---

## 7. 风险与对策

| 风险 | 等级 | 对策 |
|------|------|------|
| 获客不足（H5 自然量少） | 高 | 小米商店/快应用渠道；分享卡+裂变 |
| 次日留存 < 20% | 中高 | 日课/签到已上；用埋点看 `signin_claim`/`daily_complete` |
| 中端机掉帧 | 中 | 性能门禁 + 粒子上限 |
| 巨石 `game.js` 回归 | 中 | 门禁 smoke/verify；新逻辑进 `js/*` |
| Token 泄露 | 中 | GitHub PAT 用后 revoke |

---

## 8. Go / No-Go

| 条件 | 判定 |
|------|------|
| 核心循环与稳定性 | **Go** |
| 美术达到「可传播 MVP」 | **Go（本包强化后）** |
| 立即上 3D 全面重制 | **No-Go** |
| 立即重金买量 | **No-Go**（先验证 D1/广告 mock 再接 SDK） |

**建议决策**：继续投入 2–4 周做「表现 + 回访 + IAA 真接入」，用数据决定是否加大美术与渠道预算。

---

## 9. 指标门禁（验证 MVP）

- D1 再开局 ≥ 25%（自然量）  
- 平均局时 3.5–8 min  
- 崩溃/白屏会话 < 1%  
- 壳红点点击率、签到领取率可测（埋点已有）  
- 中端机目视 60fps / 可玩  

数据缺口：当前仅本地埋点环 → 商业化前需上报通道（平台 SDK 或自建）。
