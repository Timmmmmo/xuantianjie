## 1. 产品一句话与边界

**修真幸存者 · 碎片时间爽局**  
无尽妖潮 + 局内 build（灵石/装备/图鉴/炼宝）+ 局外回访（签到/日课/分享）。

| 做 | 不做（v2.x） |
|----|----------------|
| 单人 H5 / PWA，Canvas2D 零依赖 | 3D、多人、服务端强依赖 |
| 自愿激励视频（IAA） | 付费数值碾压、强制广告墙 |
| 原创修真包装 | 直接使用魔兽 IP 素材/名称对外宣发 |
| 中端机（Redmi 级）可玩 | 为高端机堆特效导致掉帧 |

## 2. 五条线怎么统筹（本项目实操）

### 2.1 产品创意
- 来源：玩法债（系统是否形成 build 抉择）、回访债（明天为何回来）、传播债（截图是否值得发）。
- 产出：一页创意卡（问题 → 假设 → 成功指标 → 反例）。
- **否决权**：无明确指标、无失败判据的创意不进 Sprint。

### 2.2 产品设计
- 每个可交付功能必须有 `docs/compose/spec/<feature>.md`（Compose）。
- 设计必答：用户路径、边界状态、埋点、不做清单。
- 与 v7.7 系统冲突时：**玩法主体保持 v7.7 行为**，新壳不得静默改核心手感（除非规格写明）。

### 2.3 Coding 安排
| 约定 | 说明 |
|------|------|
| 入口 | `game/index.html`；逻辑主文件 `game/game.js`（v7.8 巨石，改动需克制） |
| 壳模块 | `game/js/ads.js` · `signin.js` · `daily.js` · `sharecard.js` · `analytics.js`（window IIFE，**非 ESM**） |
| 禁止 | 双挂 Meta（不要再 `script` 引入 `js/meta.js`）；npm/打包器/three.js |
| 部署 | `.deploy/deploy.js` 白名单上传；**改静态资源必须 bump** `sw.js` 的 `CACHE` |
| 顺序 | spec → 实现 → smoke/verify → 评审 → Pages rebuild → 线上 verify |

### 2.4 游戏质量
| 门禁 | 命令/标准 |
|------|-----------|
| 语法 | `node --check game/game.js` + `sw.js` + 被改 js |
| 冒烟 | `node game/tests/logic-smoke.js`（改数值/存档/广告必跑） |
| 线上 | `.deploy/verify.js` + Pages `status=built`（**上传成功 ≠ CDN 已更新**） |
| 性能 | 中端机目标可玩；Quality 三档逻辑不得回退 |
| 存档 | 双键/缺字段不得丢图鉴、契约、签到、premium |

### 2.5 游戏测试
| 层级 | 谁 | 内容 |
|------|----|------|
| 自动化冒烟 | 研发 | 公式、存档合并、广告日限、日课发奖 |
| 自动化验收 | 研发 | jsdom：启动无错、壳 UI、关键状态机 |
| 真机清单 | 测试经理 + 用户 | 摇杆/刘海/发热/离线 PWA/签到与分享 |
| 平衡主观 | PM | 前 30 秒是否懂、死亡是否想再战、广告是否「自愿感」 |
| 回归 | 每次发布 | smoke + verify 全绿才允许部署 |

真机必测清单（发布前）：
1. 开局 30 秒：能走、能自动打、能升级  
2. 炼宝/背包/图鉴入口可开可关  
3. 签到可领、日课有进度  
4. 结算分享出图或下载  
5. 激励视频 mock 可完成/失败可恢复  
6. 切后台再回不被打死  
7. 旧存档（v2 图鉴 + v3 签到）不丢

## 4. 研发排期原则（Coding 安排）

1. **一规格一交付**：禁止无 spec 大改 `game.js`。  
2. **壳优先于挖巨石**：新回访/商业功能尽量 `js/*` 模块 + UI 接线，少动战斗内核。  
3. **存档永远向后兼容**：只增字段、深合并；破坏性变更 bump key 并写迁移。  
4. **发布**：smoke → 评审 critical 清零 → deploy → **Pages built** → verify → 真机抽样。  
5. **密钥**：GH token 只走环境变量，不进仓库；用后 revoke。
