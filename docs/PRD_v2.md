# 《玄天劫 · 刷不完的怪》产品重规划 v2.0

> 角色：小米高级游戏产品经理  
> 基线：v1.3 已上线 H5（Canvas2D 零依赖 + PWA）  
> 目标：从「能玩的 Demo」升级为「符合高标准小游戏定义、可规模化获客与留存」的产品

---

## 1. 一句话定位

**修真幸存者 · 碎片时间爽局**  
在 3–8 分钟一局的手机竖屏里，用飞剑清妖潮、叠 Combo、觉醒武器；用局外灵石与每日目标把「再来一局」变成「每天回来打两把」。

| 维度 | v1.3 现状 | v2.0 定位 |
|------|-----------|-----------|
| 形态 | 开源 H5 / PWA | 主路径仍是 H5/PWA；预留快应用/游戏中心适配层 |
| 用户 | 尝鲜修真/幸存者爱好者 | 小米中端机（Redmi 系）为主的休闲动作用户 |
| 心流 | 8–15 分钟无尽 | **速局 4 分钟** + **无尽 10 分钟** 双模式 |
| 留存钩 | Combo + 灵石商店（会玩完） | 日课 / 周挑战 / 赛季目标（玩不完） |
| 变现 | 无 | IAA 优先（激励视频），IAP 可选后置 |
| 数据 | 无 | 核心漏斗事件埋点（本地 mock → 可接平台） |

---

## 2. 目标用户与场景（小米侧）

### 2.1 主用户画像
- **设备**：Redmi Note / 数字系列为主，`deviceMemory ≤ 4GB`、中低端 GPU 占比高  
- **场景**：通勤、课间、午休、睡前——单手、竖屏、网络可能不稳  
- **动机**：短时爽感 > 深度养成；喜欢「自动打怪 + 手动走位」的低操作门槛  
- **拒点**：首次加载 >3s、发热掉帧、强制看广告才能进正局、没有第二天回来的理由

### 2.2 小米高级 PM 必守的产品原则
1. **冷启动可玩**：首包/首屏 < 3s（中端机），无网可进主循环（PWA 已具备，保持）  
2. **中端机 60fps 主路径**：画质三档自适应保留，新增「发热/低电」降档  
3. **单手竖屏优先**：触控热区 ≥ 48px（技能已 82px，保持）  
4. **合规前置**：无内购博彩感；未成年人时长提示；隐私协议最小集  
5. **可度量**：每个版本必须能回答 D1 留存、平均局时、死亡波次分布

## 3. 差距诊断（相对「高标准小游戏」）

| 能力 | 高标准要求 | 本作 | 差距 |
|------|------------|------|------|
| 核心循环 | 10s 理解、30s 上头 | 有（自动飞剑+走位） | 教学引导缺失，靠玩家自悟 |
| 单局设计 | 3–8 分钟闭环 | 无尽 8–15 分钟 | **缺速局模式**；死亡=全结束，无局中目标 |
| 回访钩 | 日活任务/赛季/推送 | 仅纪录+商店 | 商店会「点满」；无日/周结构 |
| 成长深度 | 数周可见的长线 | 7 项商店上限低 | 缺角色解锁线、皮肤、图鉴、周常 |
| 社交传播 | 排行/分享/好友对比 | 无 | **零社交**，获客只能靠口口相传 |
| 商业化 | IAA 自然嵌入 | 无 | 无广告位、无去广告、无激励点 |
| 内容节奏 | 活动/新怪/新武器 | 静态池 | 缺 live ops 编排 |
| 表现力 | 音效/特效达「完成品」 | 程序化 beep + 矢量 | 音效与打击乐感偏 Demo |
| 数据 | 漏斗+留存+平衡看板 | 无 | 无法科学调参 |
| 技术债 | 单文件可维护边界 | `game.js` ~2940 行 | 功能再涨会不可维护，需模块化门槛 |

**结论**：玩法内核达标，**产品壳（回访、社交、变现、数据、节奏）未达标**。v2.0 应把资源从「再加一种武器」转到「让玩家明天还来」。

## 4. 产品支柱（Four Pillars）

```
     ┌─────────────────────────────────────────┐
     │  P1 爽局体验   3–8min 双模式 + 手感/反馈  │
     ├─────────────────────────────────────────┤
     │  P2 回访系统   日课·周挑战·赛季·推送点   │
     ├─────────────────────────────────────────┤
     │  P3 社交传播   排行·战绩分享·好友幽灵    │
     ├─────────────────────────────────────────┤
     │  P4 健康商业   激励视频自然嵌入 + 可选皮肤│
     └─────────────────────────────────────────┘
              底座：性能/合规/数据/可维护架构
```

### P1 爽局体验
| 项 | 规格 | 优先级 |
|----|------|--------|
| 速局模式「斩妖令」 | 固定 5 波 + 终局 Boss，目标 4 分钟内通关；失败可看 1 次广告续命 | P0 |
| 无尽「天劫无尽」 | 保留现模式，作为硬核与冲榜 | P0 |
| 新手引导 | 首局 3 步强制引导：移动 → 技能 → 升级三选一；可跳过 | P0 |
| 死亡反馈 | 死亡时展示「本局曲线」：波次/Combo峰/死因（被围/被Boss砸） | P1 |
| 音效升级 | 替换 beep 为短采样包（剑击/升级/Boss 咆哮），保留程序化兜底 | P1 |
| 击顿与震屏 | 保留；Boss 死亡增加 0.5s 全屏定格 + 掉落高光 | P1 |

### P2 回访系统
| 项 | 规格 | 优先级 |
|----|------|--------|
| 日课「每日修行」 | 3 条：通关1次速局 / 连杀达到 N / 使用指定武器通关；全部完成给灵石包 | P0 |
| 签到 | 7 日循环，第 7 日皮肤碎片或大量灵石 | P0 |
| 周挑战 | 1 周 1 个主题（如「只准飞剑」「Boss Rush」），周日结算称号 | P1 |
| 赛季 | 4 周一季；赛季商店换皮肤/头像框；重置周挑战与赛季积分 | P1 |
| 推送点 | 仅 PWA/Web Push 可选；文案：「今日斩妖令未完成」——**默认关闭，设置内开启** | P2 |

### P3 社交传播
| 项 | 规格 | 优先级 |
|----|------|--------|
| 本地/云端排行 | 先做「本机历史 Top10 + 好友幽灵」；有后端后再上全服榜 | P0（本机）/P1（云端） |
| 战绩分享卡 | 结算页一键生成竖版战绩图（波次/Combo/武器觉醒列表） | P0 |
| 好友幽灵 | 分享链接带 seed+参数，好友可打「幽灵影子局」对比 | P2 |
| 社交裂变 | 分享得灵石（每日限 1 次，防刷） | P1 |

### P4 健康商业（IAA 优先）
| 位点 | 形态 | 规则 |
|------|------|------|
| 结算翻倍 | 激励视频 ×2 灵石 | 每局 1 次 |
| 速局续命 | 激励视频 +1 次复活 | 每局 1 次 |
| 日课刷新 | 激励视频重随 1 条日课 | 每日 1 次 |
| 去广告 | 一次性买断或订阅 | v2.1 后评估 |
| 皮肤/角色 | 纯外观或横向玩法角色（不卖数值碾压） | 后置 |

**原则**：不设「不看广告无法进正局」；不卖影响排行榜公平的数值。

## 5. 核心循环（v2.0）

```
启动 → 主界面（日课进度/签到/赛季）
  → 选模式：速局 | 无尽 | 周挑战
    → 选角色（3 基 + 解锁角色）
      → 局内：走位清怪 → 升级三选一 → Combo/觉醒
        → 速局：5波Boss 结算 | 无尽：死亡结算
          → 结算：灵石/日课/分享卡/(可选广告翻倍)
            → 局外：商店 / 图鉴 / 赛季进度 → 下一局
```

### 单局节奏目标（速局）
| 时间 | 事件 | 设计意图 |
|------|------|----------|
| 0–20s | 教学/回忆：飞剑自动打 | 零学习成本 |
| 20–90s | 第1–2波 + 首次升级 | 建立成长感 |
| 90–180s | 武器解锁决策 | Build 方向 |
| 180–240s | Boss | 高潮与结算张力 |

### 无尽保留
- 波次公式、精英/Boss 节奏维持 v1.2 验证过的曲线，仅调首波难度（Backlog P0）

## 6. 系统与数值（增量，不推倒）

### 6.1 保留（已验证）
- Combo：2.2s 窗，经验放大，峰值入结算  
- 灵石：`floor(wave*3 + kills*0.4 + comboPeak*1.5) * (1+coinMul)`  
- 商店成本：`floor(base * 1.55^lv)`  
- 三角色：剑/法/体  
- 六武器线 + 觉醒  

### 6.2 新增
| 系统 | 说明 |
|------|------|
| 日课奖励表 | 完成 1/2/3 条分别 30/50/100 灵石；周全勤额外碎片 |
| 赛季积分 | 速局通关 +10、无尽每 5 波 +1、周挑战 +50 |
| 图鉴 | 妖物/武器/称号收集，点亮给微量永久加成（≤5% 总强度，防数值爆炸） |
| 解锁角色 | 第 4 角色「符修」：放置符箓，偏策略；用赛季币或成就解锁 |
| 续命 | 速局 Boss 前死亡可 1 次广告复活（无尽不提供，保硬核） |

### 6.3 平衡门禁
- 无 build 首通速局期望波次：失败率 25–40%（给广告续命空间）  
- 好 build 无尽：D1 用户中位死亡波次 12–18  
- 灵石日获取：活跃用户 1–2 天可点满 1 项商店一级

## 7. 信息架构与关键界面

```
主界面
├─ 大按钮：速局（默认） / 无尽
├─ 日课进度条（3/3 宝箱）
├─ 签到入口
├─ 商店 / 角色 / 图鉴
├─ 赛季横幅
└─ 设置（音效/画质/通知/隐私）

结算
├─ 成绩 + 死因
├─ 灵石 (+广告×2)
├─ 日课勾选动画
├─ 分享卡
└─ 再来一局 / 回主界面
```

设计原则：主界面 **1 屏内完成下一次开局**；不把日课做成强制墙。

## 8. 技术与平台约束（研发必须遵守）

1. **保持零依赖 Canvas2D 主路径**，不引入 three.js/打包器作为前置  
2. **模块化门槛**：继续加功能前，将 `game.js` 拆为 `core/`（状态）· `combat/` · `ui/` · `meta/`，单文件逻辑块 < 800 行  
3. **存档**：`xuantianjie_meta_v2` → `xuantianjie_meta_v3`（含日课/赛季/图鉴），旧档一键迁移  
4. **性能预算**（Redmi 级）：  
   - 冷启动（本地缓存命中）< 1.5s  
   - 战斗 60fps（高画质）/ 45fps 可接受（低画质）  
   - 峰值内存 < 200MB  
5. **PWA**：保持离线；更新资源必须 bump `sw.js` CACHE  
6. **适配层预留**：输入、支付、登录、分享做接口抽象，便于日后接小米快应用/游戏中心 SDK  
7. **验收**：延续 `logic-smoke` + `verify.js`；新增日课/结算/分享卡的 jsdom 用例

## 11. 风险与对策

| 风险 | 对策 |
|------|------|
| 加日课变「上班感」 | 日课极简 3 条、可跳过、奖励小额 |
| 广告伤体验 | 仅自愿位；正局零强制 |
| 单文件爆炸 | v2.0 第一周先拆模块再堆功能 |
| 中端机掉帧 | 维持 Quality 三档；新增怪物密度上限配置 |
| 无后端时排行榜假 | 明确标注「本机榜」；云端后置 |
| 版权/题材 | 包装为原创修真，不直接使用魔兽 IP 素材与名称对外宣发 |
