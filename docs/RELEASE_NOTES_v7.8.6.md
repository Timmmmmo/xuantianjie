release: v7.8.6-mr —— 修「主界面只剩签到、进不去游戏」的入口事故

主人反馈：「现在主界面变成签到模块了，无法玩主游戏」。
先量后改：写了真机入口可达性审计台（tools/entry-audit.js），把「按钮到底在不在屏幕上」量出来，再动手。

== 事故（真机实测 414x896）==
- 开始页内容高 1128px，视口 896px，溢出 268px 且完全不可滚动
- 「踏入战场」按钮 top=978，被顶到屏幕外 82px，物理上点不到
- 屏幕上只剩下 日课盒(242-469) / 签到盒(489-636) / 周常盒(656-759) —— 玩家看到的就是这个

== 根因（三层叠加，缺一层都不出事）==
1. 信息架构：v7.8 把 日课+签到+周常 三盒（合计 477px）排在了开始按钮「上面」
2. 布局：body{position:fixed;overflow:hidden} + 容器 flex 居中且只有 max-height 没有滚动，
   超高内容会「上下两头同时被裁」，无处可滚
3. 触摸（最隐蔽）：html,body{touch-action:none} 会顺着祖先链把子元素的触摸滚动一并禁掉 ——
   就算补上滚动，真机上照样滑不动，兜底被二次封死

== 修复 ==
- 开始页重排：「踏入战场」回到首屏；三个回访盒收进默认折叠的「修行录」，
  徽标常显「签到 +40 可领」这类提示；折叠状态记档，玩家手动展开过就尊重其选择
- 补齐兜底滚动；横屏（896x414）单独做两列紧凑排版
- touch-action:none 收敛到玩法层（摇杆 / 技能键照旧禁手势，游戏手感零改动）
- 运行时守卫：回菜单 / 转屏 / 改窗 / 字体加载 / 尺寸变化等时机自动巡检，
  入口一旦不在视野就自动收起面板并滚回视野 —— 保证任何机型都点得到开始

== 同批修复的两项 P1（v7.8.5 遗留）==
- P1 用例波次：冒烟用例 54 断言「升级弹三选一」，但 forcePlay() 不重置波次，
  落在前 10 波（v7.5 自动悟道期）永远不弹窗 → 线上 140 PASS / 1 FAIL 的根因是「用例过时」，
  不是游戏 bug。改为显式推过自动期再测弹窗，并补反向断言锁住「前 10 波不弹窗」的设计
- P1 版本号统一：原 sw.js=xuantianjie-v7.8.5-mr / 埋点=v7.8.2-mbiz / index=v7.8.5 三处各写各的。
  改为单一版本源（game.js APP_VERSION），其余位置一律引用，并由门禁强制校验一致性

== P1-3（重跑门禁时新挖出，比上面两项更严重）：冒烟结果不可复现 ==
- 原始线上用例连跑 20 次 → 20 次全红，除确定性那条外还有 5 条断言随机红
  （濒死狂血 / applyHit 五行 / 词缀行为 / 灵石槽 / 掉率归属）
- 根因：测试桩完全没控制随机数，而 game.js 有 42 处 Math.random() —— 每次跑都是不同轨迹。
  这样的门禁「红是常态、绿是运气」，不能作发布依据
- 修法：测试沙箱注入固定种子的 mulberry32（默认种子可复现，XTJ_SEED=<int> 换种子做模糊测试），
  并修掉由此暴露的 4 条脆弱断言（狂血诀改时长 / 变类卡累积 +15% /
  暴击顿帧让 update() 整段跳过拾取 / 跨派系比例样本量不足却用 2.4σ 容差）
- 结果：模糊测试 28/28 种子全绿（修前 7/12）
